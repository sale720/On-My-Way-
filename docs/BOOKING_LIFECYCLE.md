# دورة الحجز (المنفّذة في المرحلة 2)

المصدر: `src/server/bookings/state.ts` (جدول الانتقالات)، `src/server/bookings/service.ts` (التنفيذ).

## المسار الأساسي
```
            (عميلة)                (مقدمة/منشأة)        (مقدمة/منشأة)        (مقدمة/منشأة)       (مقدمة/منشأة)        (مقدمة/منشأة)
 طلب ─► PENDING_PROVIDER_ACCEPTANCE ─► CONFIRMED ─► PROVIDER_EN_ROUTE ─► PROVIDER_ARRIVED ─► IN_PROGRESS ─► COMPLETED
              │  │                        │               │                     │                              │
              │  └► REJECTED (سبب)        │               │                     └► NO_SHOW (سبب)               └► DISPUTED (سبب) ─► REFUND_PENDING ─► REFUNDED / PARTIALLY_REFUNDED
              └► CANCELLED                └► CANCELLED (سبب، ضمن سياسة الإلغاء للعميلة)
                 (عميلة/منشأة/منصة/نظام: انتهاء مهلة القبول)
```
**الدفع الإلكتروني (D-018):** `PENDING_PAYMENT` (الموعد محجوز خلال نافذة الدفع) ← `PENDING_PROVIDER_ACCEPTANCE` بعد الدفع (نظام) أو `CANCELLED` (فشل الدفع / انتهاء المهلة / إلغاء العميلة). أي إلغاء أو رفض بعد الدفع يُطلق **استرداداً تلقائياً**. `DRAFT` و`PENDING_AVAILABILITY_CHECK` و`ASSIGNED` محجوزة في المخطط دون انتقالات بعد.

## من يحق له ماذا (Capacities)
| الصفة | التعريف |
|---|---|
| customer | العميلة صاحبة الحجز |
| provider | مقدمة الخدمة المسندة، بعضوية نشطة |
| salon | عضو بصلاحية `salon.bookings.manage` (مالكة/مديرة) |
| platform | صلاحية `platform.bookings.manage` (مدير المنصة) |
| system | آلي (انتهاء مهلة القبول، أحداث الدفع مستقبلاً) |

أي انتقال غير موجود في الجدول، أو من صفة غير مسموحة، يُرفض بـ `INVALID_TRANSITION`. موظف الدعم يقرأ فقط.

## قواعد مُنفّذة ومختبرة
1. **إعادة التحقق عند التأكيد:** التغطية، نشاط الخدمة والمنشأة، أن الموعد ضمن المواعيد المحسوبة فعلياً، وتوفّر وسيلة الدفع. ويُعاد احتساب السعر عند الإنشاء.
2. **منع التعارض ذرّياً:** قيد `EXCLUDE USING gist` في PostgreSQL يمنع حجزين نشطين متداخلين لنفس مقدمة الخدمة، حتى مع الطلبات المتزامنة. عند التعارض يجرّب النظام مقدمة مؤهلة أخرى، ثم يعيد `SLOT_UNAVAILABLE`.
3. **الوقت المحجوز** = `[الموعد − وقت الانتقال، نهاية الخدمة)`. وقت الانتقال إعداد للمنشأة إلى حين ربط خدمة توجيه (ETA).
4. **مهلة القبول:** الطلب غير المقبول يُلغى تلقائياً بعد `acceptanceTimeoutMinutes`، ولا تتجاوز المهلة موعد الخدمة. التنفيذ كسول عند القراءة والإنشاء، ويُستدعى `expireStalePendingBookings()` من مُجدول عند توفره.
5. **الإلغاء المجاني:** العميلة تلغي مجاناً قبل التأكيد، أو بعده إذا بقي على الموعد ≥ `cancellationWindowHours`. غير ذلك يُرفض بـ `LATE_CANCELLATION`. رسوم الإلغاء المتأخر مؤجلة للمرحلة 5.
6. **لقطات (Snapshots):** يُحفظ مع الحجز السعر والمدة والعنوان ومهلة الإلغاء ونسب الضريبة والعمولة. تعديل الأسعار أو التغطية لاحقاً لا يغيّر الحجز ولا يلغيه.
7. **الخصوصية:** قبل `CONFIRMED` ترى مقدمة الخدمة والمنشأة الحيّ فقط، دون الشارع والمبنى ورقم الجوال.
8. **قفل تفاؤلي:** كل انتقال يُطبّق بشرط `status = الحالة السابقة`. أي تعديل متزامن يُرفض بـ `CONFLICT`.
9. **السجل:** كل انتقال يُسجَّل في `BookingStatusHistory` مع المنفّذ والسبب، وما تنفّذه المنشأة أو المنصة يُسجَّل أيضاً في سجل التدقيق.
10. **الدفع النقدي:** يُنشأ سجل `Payment` بحالة `PENDING`، وتؤكد مقدمة الخدمة أو المنشأة الاستلام بعد بدء الخدمة أو اكتمالها (`PAID`) مرة واحدة فقط. عند الرفض أو الإلغاء يصبح `VOIDED`.
